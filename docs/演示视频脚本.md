# 演示视频脚本（5–8 分钟）

> 目标：5–8 分钟，1080p，MP4，普通话讲解，可配字幕。
> 本版成片约 **7 分 20 秒**，包含**功能介绍**与**技术栈**两个独立段落，再进入真实操作演示。
>
> 成片说明：仓库内最终成片为 **6:30**，结构为「开头静态页 + 完整录屏（从 PyCharm 启动开始，不剪） + 结尾」；本脚本保留分镜与文案参考。

## 一、录制前准备

### 1. 环境

- 分辨率 1920×1080，浏览器缩放 100%，关闭无关标签页、通知与输入法候选框；
- 提前执行 `python run.py`，确认 `/api/health` 返回 `key_configured: true`；
- 使用测试账号 `13800138000` / `Demo@123456`（`backend/seed_demo.py` 可重建）；
- 提前生成 1 份带「待确认事项」的报告，并再准备 1 份草稿，避免录制时等待模型；
- 现场只演示 1 次短对话，问题控制在 20 字以内。

### 2. 素材

| 素材 | 用途 |
| --- | --- |
| PPT 封面页 | 片头：项目名、赛道、团队 |
| PPT「功能地图」页 | 00:35–01:30 功能介绍 |
| PPT「技术栈」页 | 01:30–02:30 技术栈讲解 |
| `docs/diagrams/architecture.png` | 技术栈段落的架构总览 |
| `docs/screenshots/report-desktop.jpg` | 模型异常时的报告备份画面 |

### 3. 浏览器标签顺序

按演示顺序提前打开，避免现场找页面：

1. 首页 `http://127.0.0.1:8000`
2. 模板库 `#/templates`
3. 我的图纸 `#/history`
4. 报告详情 `#/doc/<预生成报告 id>`

### 4. 设备

- 麦克风离嘴 15–20cm，录前试音；
- 录屏：OBS / EV 录屏，1920×1080、25fps；
- 剪辑：剪映 / PR，导出 H.264 + AAC；
- 鼠标移动放慢，点击前停留 0.5 秒，方便加字幕和箭头。

## 三、分镜与口播

### 00:00–00:35 开场（35 秒）

**画面**：P1 封面 → 首页 Hero，鼠标轻移。

**口播**：

> 大家好，我们是极构团队，参赛作品是「极构 · 需求诊断顾问」，参加 AI WEB 网页开发挑战赛。
> 我们解决的问题很具体：很多创业者和个体店主想做一个系统，却说不清要做什么、大概多少钱、还缺哪些准备。
> 极构用 AI 把一句「我想做个系统」，变成一份可以直接拿去开发、询价、立项的需求报告。

### 00:35–01:30 功能介绍（55 秒）

**画面**：P2 功能地图，每说一项，右侧切入 2 秒真实界面（问卷、报告、评分、交付物、验收、模板/图纸）。

**口播**：

> 产品有六块核心能力。
> 第一，AI 问卷和自由对话：问卷会一题一题追问，自由对话适合已经有想法的人。
> 第二，五段式诊断报告：项目概述、已具备、还缺失、待确认清单、建议下一步。
> 第三，六维成熟度评分和风险提示，一眼看出需求还想清了没。
> 第四，三份交付物：PRD、开发询价清单、成本工期，外加 MVP 与完整版的 A/B 方案。
> 第五，验收版本：每次确认生成版本号、指纹和 diff，留下书面凭证。
> 第六，模板库、我的图纸和多格式导出，报告可以导出 Markdown、PDF 和长截图。
> 这就是从「一句想法」到「可执行材料」的完整闭环。

### 01:30–02:30 技术栈与架构（60 秒）

**画面**：P3 技术栈页 → 架构图，讲到哪一层就在图上高亮哪一层。

**口播**：

> 技术栈分三层。
> 前端是 Vue 3.5 + Vite 8，Pinia 管理账号、对话和报告状态，Vue Router 做登录守卫；Markdown 用 markdown-it 渲染，highlight.js 做代码高亮。
> 后端是 FastAPI + Uvicorn，AI 编排用 LangChain 1.4 和 LangGraph 1.2，模型通过 OpenAI 兼容网关接入 deepseek-v4.1-flash-1017。
> RAG 是双通道：配置了向量模型就走 Chroma 相似度检索，否则自动降级到自研 BM25，知识库是 12 篇原创文档、32 个片段。
> 数据层只用单文件 SQLite，密码用 PBKDF2-SHA256 加随机盐；PDF 用 reportlab 排版，长截图用 html2canvas。
> 整套系统不依赖数据库服务或容器，`python run.py` 一条命令启动。

### 02:30–03:15 登录与首页（45 秒）

**操作**：打开首页 → 登录页 → 输入测试账号 → 首页 → 指出两种模式。

**口播**：

> 系统是本地运行的完整 Web 应用，首次使用先注册，手机号加强度校验的密码。
> 登录后进入首页。这里给出两种诊断方式：问卷适合还说不清的人，自由对话适合已经有想法的人。
> 右上角是当前账号，报告和验收记录按账号隔离，换账号不会互相看到。

### 03:15–04:05 问卷演示（50 秒）

**操作**：开始需求分析 → 选「问卷」→ 答 2 题（形态、用户）→ 点「补充说明」→ 点「上一题」。

**口播**：

> 问卷不是固定题库，而是 AI 根据上一题动态生成下一题。
> 比如我先选「微信小程序」，再说给门店顾客用，它会继续追问核心功能和预算。
> 每道题都能补充说明，也能回上一题修改；信息够了，它会主动收尾，而不是没完没了地问。

### 04:05–04:55 自由对话与 RAG（50 秒）

**操作**：新开自由对话 → 输入「我想做奶茶店扫码点单小程序」→ 展示「正在检索知识库」→ 流式回答 → 展示代码高亮/复制（如回答含代码）。

**口播**：

> 自由对话走的是 Agent：先检索知识库，再按「已具备、还缺失、待确认」三段回答。
> 前端通过 NDJSON 接收事件，所以能看到检索状态和逐字输出；生成过程中可以随时停止，已输出内容会保留。
> 检索有两条通道：Chroma 向量检索和 BM25 关键词检索，向量服务不可用时自动降级，保证离线也能演示。

### 04:55–05:50 报告、评分与交付物（55 秒）

**操作**：打开预生成报告 → 滚动五段正文 → 六维评分与风险 → 生成/展示三件套交付物 → A/B 方案。

**口播**：

> 生成后会得到五段式诊断报告：项目概述、已具备、还缺失、待确认清单、建议下一步。
> 同时给出六维成熟度评分和风险提示，再把需要拍板的事项逐条列出来。
> 继续可以生成 PRD、开发询价清单、成本工期估算，以及 MVP 和完整版两套 A/B 方案。
> 这些不是聊天记录，而是可以直接发给开发方、用来比价和验收的材料。

### 05:50–06:35 待确认、验收与版本（45 秒）

**操作**：待确认事项 → 点「一键全部已确认」→ 进度 2/2 → 确认验收 → 展示凭证 v1 → 发起修订 → 展示 v2 与 diff（若已预生成）。

**口播**：

> 待确认事项支持逐条选择「已确认 / 不涉及 / 补充说明」，也可以一键全部确认，进度条会提示还剩几项。
> 全部决定后才能验收。系统会计算报告指纹、生成版本号和与上一版的差异。
> 以后改需求，能清楚看到每一版确认了什么，避免口头扯皮。

### 06:35–07:05 模板库、我的图纸与导出（30 秒）

**操作**：模板库 → 点「以此开始诊断」→ 首页输入框已预填模板摘要 → 返回我的图纸 → 搜索「奶茶」→ 展示状态徽章 → 点导出 PDF / 长截图。

**口播**：

> 模板库内置多行业模板和案例，可以一键把模板摘要带入首页，直接开始诊断。
> 我的图纸支持搜索、删除和状态徽章，草稿、已验收、成熟度、交付物一眼可见。
> 报告支持 Markdown、PDF 和长截图导出，手机浏览器也能直接查看。

### 07:05–07:20 收尾（15 秒）

**画面**：回到首页 / 团队信息页。

**口播**：

> 以上就是极构需求诊断顾问。它让不懂技术的人，也能先把需求想清楚，再去找开发。
> 谢谢大家。

# 技术选型速查表

## 先判断要不要后端
- 数据要保存、多人同时用、有登录和管理后台 → 必须要有后端和数据库。
- 只是单机演示、内容固定不变、纯展示 → 纯静态网页即可，不用后端。
- 内部几个人用的小工具，甚至可以用 Excel / 在线表格先顶一阵，别急着写代码。

## 按项目类型选技术方案

### 微信小程序（在微信里点开，不用安装）
- 一套代码同时出微信/支付宝小程序和 App：uni-app。
- 只做微信、追求流畅：原生小程序开发。
- 不想自己搭服务器：微信云开发（数据库、存储、云函数全托管，个人可低门槛起步）。
- 常见 UI 组件库：uView（配 uni-app）、Vant Weapp（配原生）。

### 网站 / 管理系统（电脑上打开网址）
- 主流组合：前端 Vue 3 + Element Plus，后端 Spring Boot + MySQL。
- 想快速搭一个带登录和权限的后台：若依（RuoYi）框架，开箱自带用户权限管理。
- 数据可视化大屏：ECharts + Vue。
- 简单企业官网：纯静态 HTML + CSS，或用 Hexo / Hugo 生成，无需后端。

### 手机 App（需要下载安装）
- 一套代码同时出安卓和苹果：Flutter 或 uni-app。
- 只做安卓且追求极致性能：原生 Android（Kotlin）。
- 只做苹果：原生 iOS（Swift）。

### 社区 / 内容类平台
- 要发帖、评论、点赞、关注：通常用「后端框架 + 内容数据库 + 对象存储存图片」。
- 一开始用户不多，用单体后端 + MySQL 完全够，别一上来就上复杂的分布式架构。

### 电商 / 交易类
- 涉及下单、支付、退款、订单状态流转，一定要用成熟电商框架或认真做后端，不要手写支付逻辑。
- 支付走微信支付 / 支付宝官方接口，切勿自己存用户支付密码。

## 常见第三方服务（能买就买，别自己造）
- 支付：微信支付、支付宝（个人需营业执照，个体户/公司）。
- 登录：微信授权登录、手机短信验证码。
- 消息：订阅消息、模板消息、短信平台、极光推送。
- 文件存储：对象存储（阿里 OSS、腾讯 COS、MinIO）。
- 地图：高德、腾讯地图（外卖、配送、定位场景）。
- 在线表格/表单：问卷星、飞书多维表格（先验证需求再开发）。

## 选型五原则
1. 团队会什么选什么，别为了「先进」选没人会维护的技术。
2. 客户量小就别上微服务、消息队列，单体 + MySQL 完全够。
3. 优先选生态成熟、文档全、搜得到答案的技术。
4. 能买现成 SaaS / 第三方服务就买，把开发精力放在核心业务上。
5. 先做最小可用版本（MVP）验证需求，再逐步加功能。

# 开发流程与常见术语（白话版）

## 核心术语（用大白话解释）
- 前端：用户看得见、点得到的部分。网页、小程序界面、App 界面都是前端。
- 后端：看不见的服务程序，负责存数据、算逻辑、判断权限、对外提供数据。
- 数据库：专门存数据的仓库，后端从里面读写，相当于「电子账本」。
- API / 接口：前后端之间的约定。前端「点一下按钮」，就向后端的某个接口要数据。
- 原型图：开发前的界面草图，先确认长什么样再动手写代码。
- 部署：把写好的程序放到服务器上，让别人能通过网址访问。
- 服务器：一台 24 小时开机的电脑，专门跑你的程序。
- 域名：网址（如 www.xxx.com），需要购买；国内服务器用域名还要备案。
- 备案：把网站信息登记到国家相关部门，国内服务器上线的法定流程，一般要几周。
- 测试环境 / 生产环境：测试环境随便折腾，生产环境是真正给客户用的。
- 联调：前端和后端接在一起整体跑通。
- MVP：最小可用版本，先做最核心的功能上线验证，再逐步加功能。
- 迭代：一版一版地更新，每一版加一点功能。

## 典型开发流程（九步）
1. 需求分析：搞清楚做什么，输出需求文档。
2. 原型设计：画界面草图，和客户确认。
3. 数据库设计：定好存哪些表、哪些字段。
4. 接口设计：定好前后端的数据约定（接口文档）。
5. 前后端并行开发。
6. 联调：接在一起整体测试。
7. 测试修 bug。
8. 部署上线。
9. 验收交付 + 后续维护。

## 为什么顺序不能乱
- 不确认原型就写前端 → 界面重做。
- 不定数据库就写后端 → 字段反复改，接口跟着改，前端再跟着改。
- 需求阶段多花一天，能省掉开发阶段一周返工。

## 客户最该理解的三个「工期真相」
1. 「看着简单」的功能，背后可能涉及支付、权限、数据安全，工作量比想象大。
2. 需求变一次，前面做的可能要推翻重来，所以需求阶段尽量一次定清。
3. 上线不等于结束：服务器要续费、系统要维护、bug 要修，这些都算成本。

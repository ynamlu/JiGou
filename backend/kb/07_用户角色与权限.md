# 用户角色与权限

一个系统里往往不止一类人。需求里没写清角色和权限，是最容易出严重 bug 的地方（比如顾客能看到后台数据、店员能改价格）。

## 先问：系统里有哪几类人
常见角色举例：
- 顾客 / 普通用户：浏览、下单、查看自己的信息。
- 会员 / 付费用户：比普通用户多一些权益。
- 店员 / 员工：处理业务（接单、发货、核销）。
- 店长 / 主管：看本店数据、管理店员。
- 管理员 / 老板：看全局数据、管所有账号和设置。
- 财务：看账、对账、提现。
- 平台运营 / 客服：处理投诉、退款、内容审核。

## 每类人要写清三件事
1. 能看到什么：哪些页面、哪些数据。
2. 能做什么：能执行哪些操作（增删改查）。
3. 不能做什么：哪些敏感操作被禁止（改价、删数据、退款、导出）。

## 权限设计的常见问题
- 没区分「查看」和「编辑」：谁能看、谁能改没说清。
- 数据越权：A 店店员看到了 B 店的订单。
- 删除权限过宽：谁都能删数据，误删无法恢复。
- 老板自己都不知道有哪些后台角色。

## 必问的三个问题
1. 谁来当管理员？有没有员工要分不同岗位？
2. 敏感操作（退款、改价、删数据）只有谁能做？
3. 要不要给外部合作方（供应商、加盟商）开账号？权限怎么分？

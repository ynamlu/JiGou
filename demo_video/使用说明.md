## 二、重新生成的三个步骤

```bash
# 1) 配音 + 字幕 + 时间轴（约 40 秒，20 次语音合成）
python docs/demo_video/build_voiceover.py

# 2) 真实录屏（需要先启动服务；约 6 分钟，含真实模型生成）
python run.py --no-browser        # 另开一个终端
python docs/demo_video/record_demo.py      # 主流程：登录→问卷→对话→报告→验收→导出
python docs/demo_video/record_templates.py # 模板库片段

# 3) 合成成片（约 2–3 分钟）
python docs/demo_video/build_video.py
```

画面编排在 `build_video.py` 的 `PLAN` 里：每个分镜指定「用哪段录屏 / 用哪张概念页」以及占比，例如
`"B13": [clip("main", "quiz_q1", "gen_start")]` 表示 B13 使用主录屏里 `quiz_q1` 到 `gen_start` 之间的素材。

## 三、制作要点

- **配音**：百度语音合成（`tts.baidu.com`，`per=0` 女声，`spd=5`）。原计划用 `edge-tts` 的 `zh-CN-YunxiNeural`，但本机网络下 `speech.platform.bing.com` 直连与代理均不可达，故改用百度语音。
- **语流**：以分镜为单位一次性合成整段口播，句间停顿由模型自然产生（不再是"一句一停"）；分镜之间 0.42s、章节之间 0.95s。
- **字幕对齐**：对每个分镜音频做静音检测，用「字符比例预期位置 → 最近停顿」匹配每句边界，误差通常在 ±0.2s。
- **录屏清晰度**：Chrome 以 2 倍像素密度渲染（3840×2160 采集），合成时 Lanczos 降采样到 1080p，文字比直接 1080p 录屏明显更锐利。
- **流畅度**：所有画面统一转 30fps 恒定帧率，段落之间**硬切、不做黑场淡入淡出**（淡入淡出会让人误以为卡顿）；概念页只做极缓推镜。
- **转场节奏**：每个分镜的画面时长与配音严格等长，不会出现画面等声音或声音等画面。

## 四、顺带修复的产品 Bug

`backend/agent_core.py` 里待确认事项的提示词包含字面量 JSON 花括号，却用 `str.format()` 渲染，必然抛 `KeyError` 并静默返回空列表——导致「待确认清单」永远为空、`一键全部已确认 / 确认验收` 无法触达。已改为 `.replace("{report}", report)`，修复后同一份报告可稳定抽出 7 条待确认事项。
